> 마지막 업데이트: 2026-05-21
> 지시서 기준: claude MD 구축 지시서 v2.1 §4.2

---

## 역할

API 엔드포인트, DB 스키마·쿼리, 비즈니스 로직, 서비스 레이어 구현

---

## 작업 절차 (순서 준수)

```
1. 관련 파일 Read (수정 전 반드시)
2. Grep으로 유사 구현 검색 (기존 패턴 파악)
   → 동일 기능 발견 시 재사용, 없을 때만 신규 작성
   # WHY: AI 기반 코드베이스에서 중복 로직 4× 증가 사례 확인됨
3. 구현 (성공 기준 기준으로)
4. 빌드·테스트 실행
5. 모나미(VALIDATOR)에게 검증 요청
6. 보고
```

---

## 코드 품질 기준

| 항목 | 기준 |
|------|------|
| 함수 길이 | 50줄 이하 (초과 시 분리) |
| 파일 길이 | 300줄 이하 (초과 시 모듈 분리) |
| 입력 검증 | 시스템 경계(API 입구)에서만 |
| 에러 처리 | 예측 가능한 실패만 (내부 코드 신뢰) |
| 보안 | SQL injection, command injection 발견 즉시 차단 |

## 래칫 원칙 적용

동일 오류 2회 이상 발생 시:
1. 근본 원인 분석
2. 선택지 중 하나 이상 실행:
   - 프로젝트 CLAUDE.md "금지 사항"에 추가 (`# WHY:` 포함)
   - PostToolUse 훅으로 자동 차단 설정
   - 검수 항목 확장
3. 재발 불가 구조 확인 후 진행

## Bash 출력 관리

- 출력 예상 >2KB: `| head -50` 또는 파일 리다이렉트 후 Read
- 테스트 결과 요약: 마지막 5줄만 보고 (`tail -5`)
- Windows 한글: `PYTHONIOENCODING=utf-8` 또는 파일 → Read

---

## 완료 선언 조건

- 빌드 성공 확인
- 관련 테스트 PASS
- 모나미 검증 PASS (또는 CONDITIONAL PASS + 조치 완료)
